1Where the bridge sits

A hosted Vanilla WoW policy receives no structured API from the platform — the Coworld /player socket carries credentials and lifecycle only, and the two /tcp/* tunnels are unfiltered byte pipes speaking the real 1.12.1 binary protocol. The bundled Nim player solves this by maintaining a client-state mirror and exposing typed snapshots and actions to its own bot brain. We are building the same seam for wowborg, in Python: a bridge that parses server packets into one coherent typed observation, and compiles typed intents back down into legal client packets.

2Design principles

Client honesty, inherited. The reference engine's core integrity rule carries over unchanged: the observation reports what a real client could know, and unknown facts stay explicitly unknown rather than defaulting to zero or false. Every model gets None-able fields with the same "known-mask" discipline the tensor contract uses — "zero is not silently promoted to observed truth."

State and events are different things. Most of the observation is latest-truth state (your health, who is nearby, what the loot window holds). But a large class of wire facts are transient events — an XP gain, a cast failure, a chat line, a damage tick — that would be lost if we only kept latest state. The observation therefore has two halves: a state snapshot (§3.1–3.9, 3.11) and an event feed (§3.10) of typed, sequenced events since the policy's last read. This mirrors what the proven policies actually needed: King Richard's loop is built on snapshot state plus recent_action_feedback windows.

Actions are intents with results, not packets. A policy action is a typed intent (move_to, cast, loot); the bridge compiles it into however many packets it takes and watches for authoritative confirmation. Every action produces a typed ActionResult; "sent" is never "done". This is the exact contract shape the reference engine proved (its action.json → action-results.jsonl loop), reproduced at our seam.

Completeness over minimalism, tiered by need. The space below includes everything a competitive policy will plausibly want — but implementation order matters, so every component and action carries a tier tag:

T0 · navigate needed for the current sub-goal (random-point navigation)   T1 · play needed to level and clear RFC (combat, loot, quests, vendor, death, party)   T2 · breadth full protocol breadth (taxi, guild, mail, AH, trade…)   defer identified, deliberately not built until demanded

What this is not. No module layout, no parser architecture, no schedule — this document fixes only what the policy can see and do. When we disagree with the reference engine's shapes we say so explicitly and why; silence means we adopted its proven shape.

4The action space

Typed intents, adopted from the reference engine's proven BotAction vocabulary wherever it fits and adjusted where our seam differs. Every action returns an ActionResult (§4.9). Two deliberate divergences from the reference vocabulary, both consequences of exposing windows (§3.8): a first-class gossip_select (the reference buries menu choice inside Nim), and explicit buy_item / sell_items / repair instead of only the composite sell_junk.

5What the bridge does on its own

Not actions, not observations — protocol obligations the bridge discharges automatically. Listed because the policy must be able to rely on them, and the observation exposes their health (meta.integrity, movement.correction_count):

  • Force ACKs — every speed / root / knockback / teleport / feather-fall / water-walk force is ACKed with its counter immediately (desync otherwise).
  • Keepalive & time sync — CMSG_PING every 15 s (wowborg v1 already); pong RTT feeds meta.connection.latency_ms.
  • World transfers — worldport ack + CMSG_SET_ACTIVE_MOVER on SMSG_NEW_WORLD; login-flow packets.
  • Identity resolution — name / creature / gameobject / item / quest queries issued lazily on first sight, cached forever; None until resolved.
  • Movement upkeep — heartbeat stream while moving (200 ms), stationary heartbeat, stand-up before cast/attack, one-flag-transition-per-packet encoding, spline-done acks.
  • Deadline discipline — the bridge itself honors deadline_seconds and ends the slot (the 27.8-hour-episode lesson from session 3 becomes structurally impossible).

7Deliberate exclusions & open questions

Excluded, with reasons

  • Threat/aggro tables — not in the 1.12 protocol; we expose per-unit target_guid and refuse to fabricate numbers.
  • Other units' aura durations & cast progress — not on the wire; booleans and spell ids only, matching the reference model's honesty.
  • Pet control actions — the RFC party (warrior/priest/shaman/rogue/mage) has no pet class; seedable classes include hunter/warlock, so this is a known T2+ gap, not an oversight.
  • Battlegrounds, dueling mechanics, stables, petitions/guild charters — no competitive surface today; the event/window schemas leave room.
  • Auction house — parse-later; economically irrelevant to episode scoring.
  • Navmesh-grade observations (local polygon graph à la tensor frame v3) — requires the mmap static data we deliberately deferred; the schema slot is movement + settlement kinds, so it bolts on without breaking the contract.

Open questions for review

  • Snapshot cadence & delivery — pull (policy reads when deciding) vs. push (bridge invokes policy per event batch)? Affects the policy loop shape, not the spaces; flagged now because the event-feed cursor design leans pull.
  • How much window flow to compose — loot defaults to the proven auto-take-all composite; complete_quest composes request-items → complete. Is that the right altitude, or should T1 expose only primitives and grow composites later?
  • Reward choice — complete_quest.reward_choice = 0 default matches the reference (blind). With the quest frame visible we can choose; do we want a bridge-level "best upgrade" heuristic or leave it to the policy?
  • Chat as rationale channel — replays only preserve /say; adopting "narrate decisions via chat" costs packets but buys replay-visible debuggability. Recommend yes, rate-limited.
