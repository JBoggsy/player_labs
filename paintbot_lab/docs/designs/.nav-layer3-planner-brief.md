# BRIEF: Layer 3 — the planner (weighted A*), worked proposal

Doc type: Design proposal (nav rework Layer 3). Date: 2026-08-12.
Status: PROPOSAL — awaiting James's ruling; Phase 0 benchmark complete, no
implementation yet. Author context: paintbot_lab stencil navigation rework.

## Problem & context

The stencil navigation rework (governing doc:
`docs/designs/nav-rework-sketch-2026-08-11.md`, §3.3) replaces today's TWO
planners — goal-anchored Dijkstra flow fields followed one 8px hop at a time,
plus a per-agent cached A* on the eroded 8px grid (`nav.nim:22-87`) — with
ONE weighted A*-family search that all navigation eventually routes through.
Route quality (danger, cover exposure, terrain) becomes cost terms in that
one search instead of per-objective steering hacks. Layers already shipped
and hosted-validated: Layer 1 (exact L∞ clearance field; `canStand` at
`worldmap.nim:233`, supercover `segmentClear` at `worldmap.nim:262`), Layer
2 (components/rooms/chokes/cover, v62), post re-sourcing + belief-scored
facing (v63), wide post pool (v64). Two performance landmines already
cleared en route, which Layer 3 inherits as hard requirements satisfied:
`fieldsFor` returns `lent RouteFields` (`worldmap.nim:86,675`) — no more
~1.4 MB per-call field copies — and the argument-order rule that the
routeDistance/distanceAt GOAL slot takes stable goals only (the goal keys
the lazy Dijkstra cache; arbitrary goals minted a full-grid field each —
detonated and fixed in v64).

Current A* today: 8px grid, endpoints snapped by `nearestWalkable` (up-left
bias), unroutable goal → returns the raw goal and the agent beelines
(`nav.nim:66-87`) — the exact pathologies the rework exists to kill. The
full kill of flow-following, the seven reason-string dispatch lists, and
beelines is Layer 4 (Intent contract); Layer 3 ships the planner itself.

## Phase 0 benchmark — the evidence (all decisions below cite this)

Scratchpad harness (`layer2 scratchpad: layer3_bench.nim`) ran weighted A*
on the REAL competition maps from the v62-v64 hosted batches (clearance
fields logged by the agent, decoded offline): the h2h cell (1235×659 px),
the 4-team ffa cell (1728×1728), and the giant probe map (3211×1713).
Danger was emulated with 8 synthetic believed-track blooms (radius 150 px,
peak +3.0 additive cost multiplier) — deliberately weakening the heuristic,
the worst case for A*. Edge validity "exact" = supercover canStand DDA per
edge (`segmentClear`); "endpt" = endpoint canStand only. 25 queries per
class; queries shared across configurations. Machine: M4 Pro, single
process (hosted runs 16 processes but replans are occasional, not
synchronized).

Supporting numbers: exact vs endpoint edges costs +40-70% time (giant 4px
arbitrary: 12.00 vs 6.92 ms mean) — affordable. Memory: generation-stamped
node arrays (gScore/cameFrom/closed/gen), no per-query clearing: 13 MB at
4px on the giant, 52 MB at 2px. Zero unroutable results in any class (all
sampled starts/goals were standable; component-mismatched goals are Layer
4's contract to prevent).

Budget context: the game runs 24 ticks/s (~41 ms/tick). Replans are
per-agent and occasional (goal moved, watchdog, cadence for moving targets)
— the realistic worst load is a handful of replans per second across 8
agents, not per-tick-per-agent. Worst single measured replan at the chosen
config (4px exact, w=1.0): 47 ms (giant, arbitrary goal, euclid) — a rare
worst-case blip, one-tick-ish, and the inflation valve cuts it 30× if ever
needed hosted.

## Decisions (each with rationale + evidence)

D1. **Flat weighted A*; NO hierarchy.** Worst measured config at 4px is 47
ms on the giant; typical replans are 1-12 ms. Hierarchical (PoI graph top
level + local refinement) adds an abstraction layer, path stitching
artifacts, and a second thing to test, to solve a budget problem that does
not exist. The PoI graph (rooms/chokes, v62) stays available as a fallback
if hosted reality contradicts the bench. (Sketch Q1: answered by
measurement.)

D2. **4 px lattice step (default).** 3-4× cheaper than 2px everywhere;
validity stays PIXEL-EXACT at any step because node/edge admission reads
the clearance field (`canStand`) — the step only quantizes waypoint
placement, which the Layer 5 follower smooths anyway. This is NOT a return
to the old 8px coarsening problem: the old grid was the walkability truth
(conservative, biased snap); here the lattice is only where waypoints may
land. 2px stays a config knob (`STENCIL_PLAN_STEP_PX`) for experiments.

D3. **Exact supercover edges.** Every edge admitted via the supercover
canStand DDA (same primitive as `segmentClear`), so every returned path is
engine-walkable BY CONSTRUCTION — no post-validation, no reliance on engine
wall-slide to survive route corners (slide remains a bonus for micro, per
the v60/v61 wall-slide lesson, not a route crutch). Cost measured at
+40-70% over endpoint-only checks: affordable, and it buys away an entire
class of "path clips a corner" bugs.

D4. **Heuristic: euclidean always; Dijkstra oracle for stable goals.** For
goals in the stable set (team homes, own capture point — the fields minted
at init), h = max(euclid, gridDistance × 0.999). Measured 2-4× expansion
reduction (giant stable: 27,592 → 9,681 at w=1.0). The ×0.999 clamp
addresses a real admissibility caveat: the 8px-grid Dijkstra distance can
in principle exceed the true 4px-lattice distance where the conservative
grid misses sub-cell passages, which would make the oracle inadmissible at
the margin. Phase 0 observed zero anomalies; v65's property tests bound the
actual path-cost deviation vs exact-euclid search on random maps rather
than assuming. If deviation shows up, the clamp factor drops (turning the
oracle into a slightly weaker but safe bound). Arbitrary goals (pursuit,
interception, evacuation) use euclid — they have no minted field and MUST
NOT mint one (the v64 rule).

D5. **w = 1.0 (optimal) by default; inflation is a shelved valve, not a
default.** w=1.3 collapses worst cases ~10-30× (giant arbitrary: 46.68 →
1.44 ms worst) with bounded suboptimality ≤30%, but the budget doesn't
require it and optimal paths make behavior more predictable/debuggable.
Knob `STENCIL_PLAN_WEIGHT` ships (default 1.0) so a hosted timing surprise
is a config flip, not a code change.

D6. **Cost function v1** (per-edge: octile base length × terrain × (1 +
soft penalties)):
- terrain: trench ×5 (matches engine climb-out speed, sketch §3.3); active
  puddles when GV41 activates them (bounding-box labels, loose — cost, not
  wall). Barriers/trenches/puddles NEVER become walls (they don't block
  movement).
- danger: additive bloom per believed enemy track (velocity-projected,
  fresh within `TrackTtlTicks`, same input as v63's facingScore): radius
  150 px, linear falloff, peak weight per profile. NOT the unvalidated
  belief.danger grid (sketch keeps that out of cost functions pending its
  validation experiment).
- exposure: at each node, if the cell's `coverDirs` mask leaves the node
  UNCOVERED from the bearing toward any fresh believed track within gun
  range, add exposure weight (per profile). Cheap: one bitmask test per
  fresh track per expanded node (v63's facingScore machinery,
  `worldmap.nim:583`).
- cohesion: deferred (sketch marks it optional; adding it in v1 muddies
  attribution).
Draft profile weights (Q2: start with exactly three):
  default: danger 0.5, exposure 0.25
  carrier: danger 2.0, exposure 1.0 (evade — the "carry_home should evade"
    requirement lands here)
  hunter: danger 0.1, exposure 0.1 (close distance, accept risk)
Profiles are weight bundles on the future Intent (Layer 4); in v65 all
swapped consumers run the default profile (see D8).

D7. **Replan policy (Q3): plain re-search, no D*-lite.** Cached path per
agent; invalidate when (a) goal moved > `ReplanGoalCells`-equivalent
(existing knob, `config.nim:118`, 2 cells = 16 px), (b) stuck watchdog
fires (existing progress test), or (c) moving-target cadence: every 12
ticks (0.5 s) for pursuit/interception-class goals. At ~1-12 ms per
replan, incremental replanning is complexity without payoff. Cadence knob
`STENCIL_PLAN_MOVING_REPLAN_TICKS` (default 12).

D8. **v65 ship scope: swap the A* consumers only; flow-following waits for
Layer 4.** The new planner replaces `astarWaypoint` for its current reason
set (intercept_thief, clear_grenade, rejoin, escort_carrier, fetch_*,
convert_hunt, squad_move/watch/hold, hunt_fallback), returning the same
waypoint contract to the existing follower. FlowReasons (carry_home, steal,
to_hold, to_post, early_defense, barrage_center) keep flow fields until the
Layer 4 Intent contract lands — killing both dispatch paths simultaneously
with a new search would make the matched batch unreadable (one change
class per version, the lab's standing discipline). The unroutable-goal
beeline fallback in `nav.nim:77-79` SURVIVES v65 (goals are not yet
validated — that contract is Layer 4's; the planner logs unroutable
requests to trace so Layer 4 has data).

## Alternatives rejected

- **JPS/JPS+**: requires uniform costs; the cost terms are the point of the
  rework (sketch already ruled it out; re-affirmed).
- **Hierarchical A* now**: bench says flat clears budget with 3-30× margin;
  hierarchy is the contingency, not the plan.
- **2 px default**: 3-4× cost for waypoint granularity the follower doesn't
  need; revisit only if Layer 5 micro wants finer waypoints in tight play.
- **Endpoint-only edge checks**: 40-70% cheaper but reintroduces
  corner-clipping paths that only engine slide bails out; contradicts
  "pixel-exact correctness everywhere" (sketch §2 goals).
- **D*-lite / incremental replanning**: replans are 1-12 ms; incremental
  search's bookkeeping complexity buys nothing at this scale.
- **Inflation by default (w>1)**: not needed for budget; suboptimal paths
  are harder to reason about in trace diffs.
- **Danger from belief.danger grid**: semantics unvalidated (sketch Q10
  experiment still open); believed tracks are the direct, interpretable
  source.

## Validation plan (v65)

- Property tests (scratchpad harness, house method): every returned path
  edge passes `segmentClear` (should be true by construction — the test
  guards regressions); path cost within bound of brute-force reference
  search on random small maps (bounds the oracle-admissibility caveat,
  D4); determinism; no-path iff BFS says component-disconnected.
- Corpus timing: plan_ms distribution on the three batch maps + 4ffa8
  giant; trace keys `plan_ms`, `plan_expansions`, `plan_cache_hits`,
  `plan_unroutable` (the Layer 4 data feed).
- Viewer: path debug layer in render_topology.py — click start+goal, see
  the planned route + expanded-region heatmap from the REAL production
  search via the harness (same drift-guard pattern as selection).
- Hosted: matched v65-vs-v64 batch, standard shape (12 requests / 58
  episodes, re-resolved board, paired giant probes).

## Open questions for James (the ruling points)

- P1: danger bloom shape — radius 150 px linear falloff, profile-weighted
  peak: fine as v1, or different shape/radius?
- P2: exposure term in v1 at all, or defer to Layer 4 with the profiles
  (v65 runs default profile only; danger+exposure still shape default
  routes)? Lean: keep both terms in v1 at default weights so the cost
  machinery is exercised before profiles multiply.
- P3: moving-target replan cadence 12 ticks — accept or tune later (knob
  ships regardless)?
- P4: viewer path layer in v65 scope, or split to keep the diff smaller?
  Lean: in scope — it is the inspection tool for every later layer.

## Risks

- Oracle inadmissibility at the margin (D4) — bounded by property tests;
  mitigation is lowering the clamp.
- Cost-term interactions (danger + exposure + terrain can triple-count near
  walls where tracks cluster) — v65 traces per-term totals per path so the
  matched batch's behavior diffs can attribute.
- Per-search arrays are per-process (13 MB giant): 16 processes ≈ 200 MB
  aggregate on one host — acceptable (hosted runners are per-seat
  containers), noted for the record.
- The v65 batch's behavior delta is broad (every A*-reason route can
  change shape) — expected-delta list: route geometry for the ~10 swapped
  reasons, danger-avoiding detours near believed enemies, no change to
  flow-reason movement.
