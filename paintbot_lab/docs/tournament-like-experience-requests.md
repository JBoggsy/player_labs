# Configure a representative Paintbot evaluation

1. Select the league and fetch its current participation guide, manifest and
   configuration. Record the exact game and policy identities.
2. Resolve the actual team and seat assignments. Do not infer roster layout from
   variant names. The public `battle-royale-s2` variant uses sixteen solo seats
   and play-calling control; Stencil's direct-input contract needs a matching
   game configuration.
3. If evaluating a campaign cell, read that cell's mode, map identity, seed and
   resolved roster. Verify which positions belong to the captain and allies.
   Do not substitute arbitrary geometry or partial seating for campaign evidence.
4. Match opponents, allies, roles, map/configuration and timing across the arms.
   Use the shared experience-request skill and check credits before creating work.
5. Inspect created child rows and final participant positions. Stream artifacts
   while the request runs, then report completed evidence and exclusions.

Local self-play answers mechanism and parity questions. Competitive conclusions
require representative hosted opponents. The [analysis reference](analysis-tools.md)
describes the current A/B adapter and its limits.
