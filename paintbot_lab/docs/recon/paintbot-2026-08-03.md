# Recon: Paintbot — groundwork for `paintbot_lab`

**Date:** 2026-08-03 · **Sources:** `~/coding/coworlds/coworld-ctf` @ `1633b7e` (repo HEAD,
pulled today), `~/coding/metta` @ main (pulled today, read-only), the live Observatory
(`coworld` CLI, deployed paintbot **0.7.178**), and `ctf_lab/` in this repo.

## Mission

Understand the Paintbot game deeply enough to adapt `ctf_lab` into a new `paintbot_lab`:
what the game is, how it differs from CTF, what the map variants are, how procedural map
generation works, how many agents one policy controls in each variant, and which parts of
the CTF lab (especially the beacon player) must be scrapped versus reused.

## Headline corrections to the brief

The task brief carried four assumptions that source + live data correct:

1. **Paintbot is not a separate engine build — it is the *same binary* as CTF.** One repo
   (`Metta-AI/coworld-ctf`), one Nim server (`src/ctf.nim`), one Sprite-v1 protocol, one
   `compose.yaml`. "Paintbot" is a second Coworld *game registration* whose only diff is
   the manifest template: `.github/workflows/upload-coworld-paintbot.yml:102-107` builds
   with `--template coworld_manifest_paintbot.json`; the workflow header (lines 5-11) says
   the two uploads "share compose.yaml and differ only in the manifest template".
   `grep -rin paintbot src/` → zero hits. The paintbot schema is a strict superset of
   ctf's, enforced by `tests/test_manifest_schema.nim:78-114` ("the ctf schema is a subset
   of the paintbot schema").
2. **There is no "1v1" variant.** The deployed manifest (verified against the live
   0.7.178 via `coworld show`) has exactly four variants: `2v2`, `4ffa`, `4ffa8`, and
   `default`. What plays like a 1v1 — two entrant policies, each owning (nearly) all
   eight seats of one team — is the **`default` variant**, which is literally classic
   CTF: fixed arena, classic scoring.
3. **Not all maps are procedurally generated.** `default` runs `mapPath: "arena"` — the
   same fixed 1235x659 arena as the CTF league — and in the two live rounds inspected it
   was **~half the episodes** (12/22 and 10/22). Only `2v2`/`4ffa`/`4ffa8` use
   `mapPath: "gen"`. The conclusion for the lab is unchanged (the player must handle
   arbitrary generated maps, so pre-baked nav is dead as the *primary* mechanism), but
   arena play is still a large share of the score.
4. **"Paint" is cosmetic.** Paint stains (missed shots, grenade bombs, spray-can cones)
   render on the board only — `src/ctf/global.nim:5429-5448`: "Spectator/board only: the
   POV/RL observation stream never receives these". There is **no territory/coverage
   scoring anywhere**. Mechanically, paintbot is capture-the-heart (CTF's flag, renamed
   "heart" in art/copy at 0.7.0 — `src/ctf/sim.nim:2131-2135`) with 2-or-4 teams, pot
   scoring, and procgen maps.

## The game, corrected

Same as CTF at the mechanics layer (movement, decoupled aim, hitscan gun, fog-of-war
cone+bubble, hearts on pedestals, med kits / shields / grenades / spray cans, shouts),
plus the multi-team layer (`docs/RULES.md:140-189`):

- **4-team mode** (`teams: 4`, Red/Blue/Green/Yellow — `src/ctf/sim_types.nim:617-623`):
  every team has its own heart and capture zone. Capturing a team's heart **eliminates
  that team** (GV32, `sim.nim:2193-2243`); a team wiped by kills retires its heart on the
  spot (GV33, `sim.nim:2244-2258`). **Last team standing wins** (`sim.nim:2261-2272`).
  Allies do not exist — 4-team play is pure FFA (`docs/RULES.md:166-168`).
- **Pot scoring** (`scoring: "pot"`, all three competitive paintbot variants):
  every team antes 1, winner takes the pot (`sim_types.nim:367-375`, payout math
  `sim.nim:2085-2093`). 2-team pot = **+2/-2**; 4-team pot = **+4/-1/-1/-1**. Time-limit
  draw still pays **-1 to every player** (GV21); mutual-wipe draw pays 0/0
  (`sim.nim:2059-2061`). Win rate remains the only scored objective.
- **Spray can** ("plasma arc" in code constants — `sim_types.nim:424-471`): cone weapon,
  reach 170px (GV30), half-angle ≈14°, damage 3 (lethal to a bare 3hp cog), 5 active +
  20 reset ticks, body-disc hit test (17px radius, GV30/31). Rules: `docs/RULES.md:385-443`.
- Game version at repo HEAD: **GV35** (`sim_types.nim:21` — elimination deaths excluded
  from combat-death stats).

**Live seating is messier than nominal** (round 513, `coworld episodes`):

- `default` 16 seats → `reardenr-paintbot x7, nancy-paintbot x7, arisk-ctf-nadecal x1, paintbot-focusfire x1` — two main entrants own ~a team each, stray seats filled.

**Design consequence: a policy must not assume how many of its team's seats it controls
(anywhere from 1 to 8) and must treat unknown same-team seats as allies.** Slot comes
from the `slot=` query param on the player WS URL; team = slot mod teamCount, then
confirmed from the first `self <color> …` sighting (the Nim baseline does exactly this,
`players/baseline/baseline.nim:971-975, 1452-1461`).

The live **rotation** (observed rounds 512-513, ~22 episodes each): ~10-12x `default`,
~8-10x `2v2`, 1x `4ffa`, 1x `4ffa8`. The rotation mechanism is the platform ladder's
`variant_rotation` (metta `app_backend/v2/ladders/config.py:114-129`,
`round_lifecycle.py:1385-1470` — mixed seat counts re-dealt under `team_n`); the actual
live config lives in the DB, so the observed mix is the best available evidence.

## Procedural map generation (how it actually works)

All in `src/ctf/arena.nim` (2648 lines), section banner at `:908-915`.

- **Deterministic**: own splitmix64 (`:930-961`), never std/random — one seed names one
  map on every platform.
- **Seed**: the map seed is the *episode* seed (`:2300`), and the episode seed is
  **randomized from OS urandom at startup** when the manifest pins the sentinel
  `679961` (`src/ctf.nim:7, 26-32, 80-89` — "with a public fixed seed the GV25 random
  respawn draws would be pre-computable by opponents"). **The seed is never on the wire**
  → a policy cannot regenerate the map; it must read the map from the observation.
- **Size classes** (`:922, 963-975`): `small 0.85, standard 1.0, large 1.3, huge 1.8,
  giant 2.6` (`colossal 5.2` override-only), drawn uniformly unless the variant pins
  `mapSize` (only `4ffa8` does: `giant`).
  - 2-team boards: `1235x659` scaled → 1050x560 … 3211x1713 (`:977-993`,
    `tests/test_mapgen.nim:48, 273-279`).
  - 4-team boards: square `960` scaled → 816 … 2496 (`:1250-1267`,
    `tests/test_four_team.nim:366` — `2496 = 960 * 2.6`).
- **Generator** (`generateMapAttempt`, `:1315-1892`): authors the LEFT half (2-team,
  `symRot180`/`symMirror`) or one quadrant (4-team, `symRot90` — every team's wall mask
  is the exact quarter-turn of the others'), laying vertical obstacle *columns* from
  families {stubs, diamonds, discs, chevrons}, trenches, a center feature
  (bracket/ring/walls), glass windows, med kits; then plugs open sightlines.
- **Validators** (`validateGeneratedMap`, `:1894-2085`): cover budget 40-170 permille,
  no open horizontal sightline, corridor width ≥26px + BFS connectivity between all
  flags and center, open-flank checks. Retry seed, seed+1, … (`generateCtfMap`,
  `:2087-2103`).
- **4-team layouts** (`docs/RULES.md:146-160`): `corners` (team per corner, diagonal
  endzone threshold) or `plus` (team per edge midpoint, arm-mouth endzone), coin-flipped
  from the seed.
- **Endzone archetypes** (2-team): classic `column` half the pool, else compact `disc` /
  `square` (`:1384-1390`).
- The resolved map is pinned as `mapSpec` JSON into the replay (`sim_config.nim:446-453`)
  — replays carry exact geometry; post-hoc analysis tools can read it.

## How a policy learns the map (the whole contract, at t=0)

The init snapshot tells the policy everything about terrain; fog hides only entities:

1. **`walkability map` sprite** (`labels.nim:80-83`): full-map RGBA sprite, alpha =
   walkable bit per map pixel, always unscaled 1x. Built at `global.nim:2947-2960`, sent
   in the player init (`:3969-3976`). **This is the nav source.**
2. **`game teams <count> map <width>x<height>`** marker (`labels.nim:123-130`,
   `docs/RULES.md:711-718`): teams (2 or 4) and exact map pixel size, stated outright.
3. **`endzone <color> <shape> <x0>,<y0> <x1>,<y1>`** markers, one per team
   (`labels.nim:141-151`): home capture region corners + shape token from
   {`column`,`square`,`disc`,`corner`,`arm`} (`labels.nim:183-189`). Caution: the
   spectator stream also carries `endzone <color> power <n>` glow overlays — match the
   third token.
4. **`Room <color> Base` markers** and the team-score chips (`team score <n>`, layer 11)
   are also on the player stream.
5. **No variant id, no game name, no mapPath, no seed, no scoring rule on the wire.**
   A policy distinguishes `default` from `2v2` only by geometry (fixed 1235x659 arena
   vs generated), and `4ffa` from `4ffa8` only by map size / seat count.

Protocol deltas from Sprite-v1 (all shared with CTF, `docs/PROTOCOL.md`): bit 7 = C
button (grenade hold-throw); `own aim <brads>` readback; do NOT send Player Ready in
league play; map camera object (id 1) presence = match running; player stream is 1x.

## The Nim baseline proves online nav is enough

`players/baseline/baseline.nim` (3118 lines) — the bundled reference bot — handles every
variant with **zero pre-baked data**: it reads the walkability sprite, erodes it by the
player footprint into an **8px grid** (`NavCell = 8`, `:104`; `buildNavGrid` `:957-1018`),
derives cover cells and exposure, and runs a Dijkstra cost field refreshed every
`RepathTicks = 10` (`:105`). Multi-team support is one gate (`GameTeams > 2`,
`:424-425`): team/role from `slot mod/div GameTeams` (`:971-975`), strategy frame
re-anchored on the real endzone geometry (`deriveMultiFrame` `:914-953` — raid target =
enemy zone with largest horizontal offset), every non-own color a threat (`:1541-1546`).
Known baseline gap: on `4ffa` (4 seats/team) its seat-role ladder never assigns
Overwatch/HomeDefender (`:427-457, :832`).

## How the campaign works (backend, all merged to metta main)

- A league's settings hold ONE round brain: `ladder` XOR `campaign`
  (`league_settings_schema.py:69-71`). Switching is a live settings-API/UI
  action — no migration; all state lives in `League.commissioner_state`
  (`campaign_v1`).
- **Board**: W x H grid (live: 10x10), 4-neighbor adjacency. The board starts
  empty; players enter by **airdrop** and expand by **invading adjacent
  cells** (max 3/round). Stakes: attacker 2-0 takes the target; defender 2-0
  takes the attacker's staked source; 1-1 status quo. Airdrops/claims vs
  filler are unstaked. Win condition = territory count.
- **An LLM strategist plays commander**: one Anthropic call per player per
  round (`strategist.py`; forced tool use, `invade`/`pass`), fed the board,
  frontier, head-to-head record, and the player's **private standing-orders
  prompt** (settable via API / new `coworld campaign set-prompt` CLI). The
  strategist picks WHERE to fight; the policies decide who wins. **A paintbot
  player's competitive kit now includes its commander prompt.**
- **Battle modes** derive from each cell's variant team structure
  (`episodes.py:144-155`): 2-team variants (default, 2v2) → mode **2v2**
  (captains + mirrored allies, both seatings played, captains swapped);
  4-team variants (4ffa, 4ffa8) → mode **ffa4** (≤4 policies: attackers +
  defender + ex-owner recruits, filler-padded; a 4-team *claim* is the
  attacker vs baseline filler on the other three teams).

## THE map-selection change (the headline for the lab)

**Every cell permanently owns a map.** At board creation each cell is stamped
(`campaign/state.py:116-148`):

- `map_ref` — a Coworld variant id (live mix: 29x `4ffa8`, 26x `4ffa`,
  25x `default`, 20x `2v2`);
- `map_seed` — `crc32("campaign-map:{seed}:{cid}") % (2^31-1)`
  (`state.py:50-53`: *"a cell IS a map — the same cell replays the same
  terrain every round"*). **All 100 live cells have pinned seeds.**
- `map_size` — drawn from weighted size classes when the game supports the
  knob (live mix: 40 standard, 25 large, 14 small, 14 huge, 7 giant).

Per episode, `_cell_overrides` (`episodes.py:213-222`) injects the **target
cell's** `mapSeed` + `mapSize` into `game_config_overrides`, merged over the
variant config (`round_lifecycle.py:1319`) — *iff* the game's manifest
`config_schema` declares those properties. **Verified: deployed paintbot
0.7.178 declares BOTH `mapSeed` and `mapSize`** (and the engine consumes
mapSeed: `arena.nim:2300` `genSeed = if config.mapSeed != -1: config.mapSeed
else: config.seed`). The per-episode `seed` still varies (crc32 of
division+round + job index — drives respawn RNG etc.), but **terrain is a pure
function of the cell**.

Consequences:

1. **Maps are enumerable and reproducible offline.** The API exposes all 100
   `(map_ref, map_seed, map_size)` triples (`GET .../campaign` → `map_refs`,
   `map_seeds`, `map_sizes`, row-major), and the generator is deterministic
   public code — we can regenerate every board's exact terrain locally
   (`generateCtfMap(map_seed, overrides, teams)` at the deployed ref).
   **Per-map preparation is back on the table** — not as a baked-in single
   arena, but as an optional per-cell knowledge layer on top of stencil's
   online model (which remains correct and necessary: the policy still can't
   read the seed from the wire; it can only recognize terrain it has seen).
2. **You always fight on the TARGET cell's map** — defense is on your own
   fixed terrain; assaulting a given cell replays the same map every attempt.
3. Cell identity is stable but not eternal: a coworld redeploy that drops a
   variant remaps affected cells deterministically (`state.py:89-98`); a
   campaign **restart** rebuilds the identical board from the same seed.
4. `default` cells still exist (25 of 100) — the fixed classic arena remains
   ~a quarter of the territory.
