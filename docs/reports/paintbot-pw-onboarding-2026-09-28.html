Paintbot PW: an onboarding guide

For James, before the selection of the first Paintbot PW policy. Revised 2026-09-29. We researched it against paintbot-pw d0728ab1 (coworld-v0.3.79), the build that the league uses on that day. Live recordings show rules 48, but rules 48 changed only FFA-kin, so the teams game plays rules 47.

Executive summary

Paintbot PW is Paintbot, rebuilt in Polyworld. Polyworld is a deterministic game engine that is written in Nim. Sixteen cogs (the name of the game for its small wheeled robots, one for each seat) play in two teams of eight. Red has the even seats and Blue has the odd seats. The teams fight for ten heart towers on an island with the name Heartwick. Each seat is a small BASIC program, and the game itself runs that program one time in each tick. Thus a "player" is a text file. It is not a container, and it is not a network client. A cog that stays near a heart for three seconds captures it. Owned hearts fill the meter of the team. The first team to 900 meter points wins, or the team with the higher meter wins at ten minutes. A team that has no lives left on any cog loses immediately. Fights are short and dangerous. Each cog has three hit points, four lives, and a paint gun that fires one shot each second. Friendly fire is on, and each cog can see only forward, in a cone. In the league, 78 of 80 recent matches stopped with an elimination, and the median match took 82 seconds.

For strategy, the most important fact is this: the winner and the score are two different things. The heart meter decides the winner. But the platform receives a different number, glory. Glory starts at 600, decreases by one each second, and gets four small awards. The loser gets zero glory, and a draw gives zero to both sides. Since the evening of 2026-09-28, the Elo of the league counts the glory margin, not only the result. Each episode gives clamp(0.5 + (our glory − their glory) / 2000, 0, 1). Thus a win with 500 glory gives 0.75, and a win with 0 glory is a draw. A fast loss costs more than a slow loss. As a result, speed is rank. The policy language is a very small BASIC that has only integers. It has a large budget for each tick (50,000 instructions, and the peak of base.bas is 9,116). It also has observations that fog controls, and a small set of actions. The engine changes many times each day. But its replays play again correctly across versions. The lab also has a set of tools with a hash check (pw.py) that changes each episode into tables, metrics, and reports.

1 · What Paintbot PW is, and what it is not

  • It is a separate coworld, paintbot-pw. It has its own source repository (Metta-AI/paintbot-pw), league, forum, and wiki.
  • It uses Polyworld, the same family of Nim engine as Gods of the Arena. It is not the Season 1 capture-the-heart shooter, and it is not the Season 2 battle royale that paintbot_lab studies.
  • The runtime is player_runtime: game-hosted. You upload one BASIC file (or a neural-BASIC ZIP), and the game runs it. There is no player container and no network protocol.
  • This coworld has one league, the teams ladder paintbot-pw. Heartland, the free-for-all "kin" mode, became a separate coworld on 2026-09-28 (Appendix A).

Three different games on the platform use the Paintbot name. Thus it is easy to move an assumption from one game to a different game by mistake. The older paintbot coworlds are the Season 1 capture-the-heart shooter and the Season 2 battle royale with WASM "plays". The Stencil player of the lab is for those games1. Paintbot PW keeps the look (paint, cogs, hearts). But it makes the game again in Polyworld, with different rules, a different player format, and a different replay format. As a result, nothing from paintbot_lab is correct here until you do a new check of it2.

The source repository is a standalone copy of Polyworld. Its history starts at "initial import of polyworld code" (2026-08-25). The game itself is in the paintbot folder under examples (approximately 14,400 lines of Nim at d0728ab1). The code that connects the game to the platform is in the paintbot folder under coworld. The deployed manifest points to the repository address, but it does not give a commit. Thus the release tag coworld-v<version> is the only link from a release to its source. The pw.py deployed-ref command of the lab finds that link3.

How to upload. The player protocol in the manifest accepts "one raw UTF-8 BASIC source file or a neural BASIC ZIP containing manifest.json, policy.bas, and model.bin"4. Before version 0.3.33, the game also accepted WASM. Now a WASM file causes the seat to forfeit5.

2 · A match from start to finish

  • Each paintbot-pw match has 16 seats, and the team of a seat is the seat number mod 2. Even seats are Red ("Ember"), and odd seats are Blue ("Azure").
  • The game has 24 ticks each second. A teams match has a maximum of 14,400 ticks (10:00).
  • There are ten equal hearts. At the start, each team owns one heart, and eight hearts are neutral.
  • A capture takes 72 ticks (3 s) with no opponent, within 140 units. More cogs do not make the capture faster.
  • The meter of a team increases by one tick-point for each owned heart in each tick. At 21,600 tick-points, the team wins. The viewer shows this value as 900 points (tick-points ÷ 24). That is five hearts for three minutes.
  • A team is eliminated when it has no cog alive and no lives left. Then the meter of the other team becomes full immediately. Almost all league matches stop in this way.

Seats and teams

The team of a seat is simply slot mod 26. Since rules 46 (0.3.75), each match sets its number of seats from the roster in the game configuration, one seat for each player token. The engine accepts 2 to 256 seats7,8. But the configuration schema of paintbot-pw requires exactly 16 tokens. Thus each paintbot-pw match has 16 seats, and other sizes occur only in local runs and in Heartland9. The manifest lets a configuration give a team label to each seat, but the engine never reads those labels7. In the league, each episode puts two policies against each other. One policy fills all eight even seats, and the other fills all eight odd seats. Thus a team is eight copies of one file10. The seats make decisions in the order of their numbers. But on odd ticks, each even and odd pair changes places, so neither team always moves first11.

Hearts and capture

A cog "touches" a heart when three conditions are true. The cog is alive. The cog is within 140 units (1.4 m, because one unit is one centimeter). And the cog has a clear path to the heart, with no step in height of more than 25 units in each 20-unit sample11,6. The progress of a capture follows a small state machine.

Source for Figure 111. In practice, the paused state is rare. The league had only 12 contests in 80 episodes12. A contest needs cogs of both teams within 140 units of the heart at the same time, but guns reach 5,250 units. Territory is the colored region on the screen near each heart. In the teams game, territory has no effect on the play. Its increase in speed and accuracy occurs only in Heartland6. Each script can read the positions of the hearts, their owners, and the progress of each capture (section 7).

Lives and spawning

Each cog has 3 base hit points and 4 lives: the first life and three more lives6,11. A dead cog comes back after 72 ticks, and it has 36 ticks of spawn protection. A death removes the grenade, the spray can, the armor, and the disguise of the cog6,11. If a team owns hearts, its cogs come back within 350 units of one of those hearts. The engine selects the heart with a softmax that prefers hearts far from the teammates that are alive. If a team owns no hearts, its cogs come back in the end zone of the team6.

How a match ends

Each end of a match goes through one line. That line sets the winner from the meters, and then it calls settleGlory11. An elimination decides the match, because the engine first makes the meter of the survivor full. If both teams are eliminated in the same tick, the engine compares the meters as they are11. In 80 league episodes of 0.3.79, 78 matches stopped with an elimination and 2 with a full meter. No match got to the time limit, and no match was a draw12.

3 · Winning versus scoring: glory

  • The meter selects the winner. The score is glory, and only the team that wins keeps it.
  • Glory starts at 600 (the length of the match in seconds). It decreases by 1 each second, to a minimum of 0.
  • The league configuration has four awards. A team gets +10 for each 30 s with no team pickup, and +20 for each glory heart (a temporary bonus pickup, not a control heart). It also gets +5 for each life behind in each 5 s. And it gets +10 for each additional cog out of the match in each 5 s.
  • The Elo of the league counts the glory margin. Each episode gives clamp(0.5 + (our glory − their glory) / 2000, 0, 1). Thus each point of glory in a win changes the rank.
  • The results: a fast win has more value than a slow win. A loss to a fast winner costs more than a loss to a slow winner. And a win with no glory left counts as a draw.

A glory heart is a temporary bonus pickup. It is not one of the ten control hearts that decide the match. The two items have the same word in their names, but they have no other relation.

Three details are important for a policy that tries to get glory. First, the clock for quiet supplies starts again only when a teammate actually takes a pickup. A cog takes a pickup only when the pickup is useful (for example, a medkit only when the cog is hurt). Thus a cog at full health can walk over a medkit, and the clock does not start again11. Second, glory hearts come in mirrored pairs from 0:20, every 10–20 s. Each one stays for 30 s, and fog hides glory hearts as it hides other pickups6. Third, each teams variant sets "glory": {"behind_lives": 5, "behind_cogs": 10}. Commit 0ff41d2 changed the cogs award from 5 to 10 in 0.3.77. All 80 league tapes of rounds 2382–2388 have exactly this configuration9. The local.py script of the repository cannot set glory, and it uses the engine defaults (1 and 1). The pw.py local command of the lab and paintbot-headless --glory:<json> use the league values13. A script can read the scoreboard: glory(team), teamLives(team), teamCogsOut(team), and the configured awards awardBehind(), awardBehindSeconds(), awardBehindCogs(), and awardBehindCogsSeconds()14.

From episode score to league rank

The Elo code of the ladder compares the average scores of the two sides. The league sets margin_scale: 1000, so the code records the margin of the scores, not only a win, a draw, or a loss15. The live settings of the league are k_factor 32, initial_rating 1500, round_scoring_rule mean, and margin_scale 100010. Until the evening of 2026-09-28, the ladder used only win, draw, or loss. Then metta commit 6304974ffa set margin_scale. If an episode fails and the platform connects the failure to one policy, that side gets 0, and the margin has no effect15. The loser always has 0 glory. Thus a win gives 0.5 + winning glory / 2000, and a loss gives 0.5 − their winning glory / 2000:

Source9. In practice:

  • Speed is rank. Each second of a match costs 1 glory, and that is 0.0005 of Elo outcome. In 80 league episodes of 0.3.79, the winners got 458–996 glory, with a median of 544. That is an average outcome of approximately 0.78. The glory of a winner was the start value of 600, a countdown of −88, and +42 from all awards together. The awards were glory hearts +15.5, behind in lives +16, behind in cogs +7.9, and quiet supplies +39,12.
  • A fast loss costs more than a slow loss. If you make the win of an opponent slower, the loss of rating decreases, also when the loss is certain.
  • The two "behind" awards pay the team that loses the fight, but they have value only if that team also wins. A team that is 3 cogs behind for one minute gets 12 × 30 = 360 glory from cogs alone. In the league data, the losers had an average of 518 glory from lives and 294 from cogs before the settlement. The settlement set all of it to zero. The one win with 996 glory came from a team that was behind and then won on the meter9.
  • Supplies cost glory. Each pickup that a teammate takes stops the current quiet period (+10 for each 30 s).
  • The win rate and glory are two different questions. A policy that wins 60% slowly can have a lower rank than a policy that wins 50% fast. For this reason, the primary A/B metric of the lab is the outcome of each episode, as above.

4 · Combat and the battlefield

  • One unit is one centimeter. A body has a radius of 55 units and moves 28 units in each tick.
  • The gun: a 5-tick windup, then a hitscan ray to 5,250 units. It fires one shot each second, and friendly fire is on. In the league, the gun makes 95% of the kills of enemies.
  • A spray can replaces the gun, and it never becomes empty. A grenade goes over walls and causes damage to all bodies in the blast, and that includes the cog that threw it.
  • Armor, or a position in a trench, makes the gun cooldown three times longer.
  • Vision is a 120° cone to the front. It has no limit in distance, but terrain stops it. Sound gives only a direction and a distance band.

Movement and terrain

A cog moves 28 units in each tick. Sneak makes this speed half, water makes it one quarter, and a cog that leaves a trench moves five times slower on each axis6,11. Bodies block all other cogs, and a blocked cog moves to the side6,11. The engine finds the path for you on a one-meter grid. On that grid, a lake cell costs four times more than a dry cell. Since rules 45, the engine also sends a cog into water when the goal itself is in water. That change lets cogs get to the lake heart6. The area of Heartwick that cogs can use is 160 × 96 m. It is symmetric under a half turn about (3200, 2000), and it has an inland lake6.

As a result, most misses occur because the target moves during the windup (we calculated this from the limit of the random error)11. For this reason, the baseline policy aims ahead of its target and moves in short random legs (section 9). The league plays mostly with the gun. Of 3,828 kills of enemies in 80 episodes, the gun made 3,621 (95%), grenades made 164, and spray made 43. Grenades also killed their own throwers 100 times13.

Vision and hearing

Each cog sees a 120° cone around its current aim point. The cone has no limit in distance, but cover and terrain block it from an eye height of 120 units6. The aim point stays from one tick to the next. lookAt and shootAt set it. If a tick has no aim call, walkTo sets it11. Thus a cog sees only the direction that it faces, and a cog that walks turns to face the direction of its walk. The rules also include vision that all cogs of a team share, but only as an option, and no deployed variant uses it.

Sound comes from footsteps (1,000 units, but not during sneak), gun shots (3,500), explosions (5,000), and spray (1,800). A sound gives only its type, one of eight compass sectors, a distance band, and its age. It never tells who made the sound11. Speech is different. A shout goes to all cogs on both teams that are alive and within 12.8 m. Each listener gets the exact position of the speaker14.

5 · How a policy runs

  • Each seat has one file and one virtual machine (VM), and the VMs do not share memory. Eight copies of your file are one team.
  • In each tick, each seat that is alive runs its script from the first line. Dead cogs do not run.
  • Global variables and arrays stay from one tick to the next. The string pool and the command of the tick do not stay.
  • All 16 scripts read the same frozen world. Then the world moves one step with all their commands.
  • The engine keeps some intent from one tick to the next. The walk goal and the aim point stay, but the trigger does not stay.

Sources14,7. The restart() function of the VM clears the registers and the budgets, but it keeps the globals and the arrays16. Thus the setup that occurs one time is a check of a flag at the top of the file, as in base.bas:

if started = 0 then
  started = 1
  rngState = selfId * 4099 + 977
  lastX = selfX
  lastY = selfY
end if
myVX = selfX - lastX
myVY = selfY - lastY

What persists between ticks

The engine clears the commands in each tick14. But the cog itself keeps some state11:

Call Stays to the next tick?
walkTo(x, y)Yes. The cog walks to the goal until a new walkTo or a respawn.
lookAt(x, y) or shootAt(x, y) aimYes. The aim point is also the center of the vision cone.
shootAt triggerNo. Call it in the tick when you want to fire.
chargeGrenade(1)No. The charge stays, but a tick without the call throws the grenade.
sneak(1)No. Call it in each tick.

Remember the grenade row, because it is a trap. A script can charge a grenade, and then, in the next tick, go into a branch that does not call chargeGrenade(1). In that condition, the cog throws the grenade in the direction of its current aim.

6 · The BASIC dialect

  • The language is the BASIC of Polyworld. It has only signed 32-bit integers, IF/WHILE/SUB, fixed arrays, and PRINT.
  • It has no FOR and no user-defined functions that return values (only SUB). The calls of the host, for example controlX(i), do return values. It has no built-in math (ABS, SQR, RND), no floating point, and strings only as handles.
  • An integer overflow wraps with no error. A division by zero or an array index out of range is a runtime error, and it stops the seat.
  • The budget for each decision is 50,000 instructions and 125,000 work units. The peak of base.bas is 9,116 instructions (18%). The guide and the headers of the starter files still give 20,000.
  • The fixed limits are 128 KiB of source, 512 globals, 4,096 array elements in total, and a call depth of 16.

The dialect is small, so this report can list all of it. The reserved words are and call dim else end exit false gosub goto if let mod not or print rem return stop sub then true wend while xor. The words goto and gosub are reserved, but the compiler makes no code for them16.

Feature Behavior
ValuesSigned int32. + - * wrap on overflow. / and MOD truncate toward zero16.
Precedence, low to highOR XOR, AND, comparisons, + -, * / MOD, unary - + NOT. NOT binds tighter than =, so write NOT (a = b)16.
VariablesGlobal. The first use makes the variable, with the value 0. The parameters of a SUB are local, and all other variables that a SUB sets are global16.
ArraysDIM name(N) at the top level with a literal bound, inclusive: DIM a(15) has 16 cells16.
Control flowIF cond THEN … [ELSE] … END IF, and WHILE cond … WEND16.
SubroutinesSUB name(a, b) … END SUB, with no return values. Give results through globals16.
PrintingPRINT "a"; x writes to the private log of the seat. The limits are 1,024 bytes and 128 print events for each decision, or the seat stops16,14.

The language has no square root. Thus base.bas has its own integer isqrt with Newton's method, and that subroutine gives its result in the global root. All helpers give their results in the same way: a SUB writes a global.

A complete minimal policy

The smallest useful policy is short. It sends each cog to the nearest heart that its team does not own, and it shoots the nearest enemy that it can see:

' Minimal Paintbot PW policy: go to the nearest heart we do not own,
' and shoot the nearest enemy we can see.
target = -1
best = 2147483647
i = 0
while i < heartCount()
  if controlOwner(i) <> selfTeam then
    dx = (controlX(i) - selfX) / 10
    dy = (controlY(i) - selfY) / 10
    if dx * dx + dy * dy < best then
      best = dx * dx + dy * dy
      target = i
    end if
  end if
  i = i + 1
wend
if target >= 0 then
  walkTo(controlX(target), controlY(target))
end if

foe = -1
best = 2147483647
i = 0
while i < 16
  if i mod 2 <> selfTeam and visible(i) then
    dx = (playerX(i) - selfX) / 10
    dy = (playerY(i) - selfY) / 10
    if dx * dx + dy * dy < best then
      best = dx * dx + dy * dy
      foe = i
    end if
  end if
  i = i + 1
wend
if foe >= 0 then
  shootAt(playerX(foe), playerY(foe))
end if

This short example shows three habits of the dialect. First, the code divides each distance by 10 before it squares it. This keeps the arithmetic safe on the big generated maps, where 50,000 units squared overflows int32 (on Heartwick, an overflow cannot occur). Second, the code gets the team from the seat number (i mod 2). A uniform can deceive this check, as it can deceive playerTeam, because a disguised enemy uses the seat number of a teammate. Third, the script starts again from the top in each tick, so it does not need a primary loop.

This policy compiles and runs. For this report, we ran four local matches against base.bas at 0.3.79 with the glory configuration of the league. We used seeds 2026 and 2027, with each policy one time on each side, and pw_trace did a hash check of each match. base.bas won all four matches. It eliminated the minimal team between tick 1,245 and tick 1,418, in less than one minute. At the end, it held 4 or 5 hearts against 1. The winners kept 541–569 glory. The minimal team got 860–1,160 glory from the behind awards, and the loss set all of it to zero. That is the lesson of section 3 in a small example. This large difference is the reason to start from base.bas and not from nothing.

7 · What a policy can see and do

  • Always public: the hearts (positions, owners, capture state), the scoreboard of both teams (glory, lives, cogs out, award settings), the map geometry (bounds, height, water, trenches), and the number of pickup stations.
  • Fog controls: other cogs, ready pickups, and glory hearts. A script can see them only in its cone.
  • Actions: walkTo, lookAt, shootAt, chargeGrenade, sneak, and shout.
  • A disguised enemy uses the seat number that it copies. heardX/Y give the exact position of a speaker.
  • Each query gives −1 (or 0 for HP) when the item is hidden or not correct. Thus a hidden cog and a cog that does not exist look the same.

The host API is a set of read-only values and functions with names, and all of them give int32 values14. Coordinates are in world units, and "Y" is the second horizontal axis, which the engine calls z. Appendix B has the full list. The general shape is this:

Some details change how you write scripts:

  • A script cannot read the gun cooldown of its cog. Thus base.bas keeps its own countdown (gunWait) and sets it to zero after a respawn.
  • A pickup that is not ready looks the same as a pickup out of view. Both give −1. Thus a policy records the time of each pickup that it sees.
  • nearAgents costs less than a loop of visible(i) in large games. The file nearby.bas17 in the repository is base.bas written again in that way18.
  • The scoreboard calls are recent. teamLives came in 0.3.72. teamCogsOut and the award calls came in 0.3.75 (rules 47). All of them give −1 in FFA-kin19. base.bas reads none of them.
  • Six fields are dead. carrying, heartX/Y, ownHeartX/Y, ownHeartStolen, and playerCarrying come from the capture-the-flag rules before rules 13. Under rules 47, nothing sets carrying, so these fields give fixed values11. base.bas still reads playerCarrying. This causes no damage, but it can confuse a reader.

8 · How policies fail

  • If the host does not accept a file (WASM, more than 128 KiB, not UTF-8, or a neural ZIP that fails its checks), only that seat forfeits. The other 15 seats continue.
  • A BASIC compile error causes the failure of the full episode, and no seat gets results.
  • A runtime error (the budget is exceeded, a division by zero, a bad index, the print limit) stops that seat until the end of the episode. The match continues.
  • A stopped cog continues to walk to its last goal, but it never shoots again. It still counts in the lives of its team.
  • In the league, 3 failures in sequence disqualify an entry. A failure that the platform connects to one policy is an Elo forfeit (outcome 0).

The compile error is the most important row. In a local test, a seat with a syntax error wrote {"message":"BASIC compilation failed for player slot 1","failed_policy_index":1} and gave no results. Then local.py stopped only at its deadline of ten minutes13. The failure record gives a policy index. Thus it is possible that the league connects the failure to the side that uploaded the file. Then the Elo code gives that side a forfeit15. We did not see this connection in a live league. Also, the league disqualifies an entry after 3 failures in sequence10. Thus submit only a version that completed hosted episodes. The guide says that "the episode still starts" when a seat fails, but this is true only when the host does not accept the file. A call to a Heartland-only function such as kin() in the teams game is also a compile error. Thus, if one file calls those names, it cannot operate in both modes. The pw.py local compile command of the lab does a check of a file in all 16 seats before an upload.

We know the behavior of a stopped cog only from the movement code, not from a test. The cog gives no new commands. Thus it continues to walk to its last goal with its last aim, and it never fires. After its next death, it stays at its spawn point. It still counts in the lives of its team, so opponents can kill it again and again11.

9 · The starter policies

  • base.bas (677 lines) is the baseline of the league and the reference design of the maintainer. Start with this file.
  • It uses habits that the maintainer measured one at a time. The cog aims ahead of the target, and it never walks in a straight line when an opponent can see it. The cogs move in squads of four, refuse fights that they will lose, and go around water.
  • Three league champions (zhar, richard, relh) come from base.bas, and one champion (Beta) comes from jev.bas.
  • jev.bas is base.bas with an LLM advisor layer. Without an advisor, it plays exactly the same as base.bas.
  • base.bas ignores glory fully. It takes supplies, never goes to glory hearts, and never reads teamLives or teamCogsOut.

base.bas

All cogs run the same file. In each tick, each cog does ten steps21,19. The copy in the lab is the file that the league uses at d0728ab1. The only differences from 0.3.65 are array sizes and loop limits, which increased to 64 for the big maps. All lines stay at the same numbers:

  1. Scan. The cog looks at all 16 seats for the best enemy that it can see within 52.5 m, with a preference for hurt enemies. It also counts the foes within 26 m and the friends within 12 m21.
  2. Squads. The seats make two squads of four from (selfId / 2) mod 8. Each squad selects the nearest heart that it does not own, as measured from a point above or below home. Blue uses the mirrored point. Two members stand in the ring, and two members give cover from outside. The members do not talk: each member calculates the same selection from the public ownership of the hearts21.
  3. Supplies. The cog remembers each pickup that it saw for 10 s. When no enemy is near, it goes to get an item. It gets a grenade if it has none, a medkit if it is hurt, or armor if it has full HP21.
  4. Refuse bad fights. If more foes than friends are near, the cog goes to the heart that is far from the foes21.
  5. Look. If the cog has no target, it looks in four directions, one after the other. It can also turn to the last speaker, or to the sector of the last gun shot21.
  6. Footwork. In a fight, the cog walks random legs of 3–9 ticks across the line of fire. It fires only at the start of a leg that is long enough for the windup21.
  7. Dry route. If the line to a target goes across water, the cog goes around through the best of six side points21.
  8. Aim. The cog aims ahead of the target by six ticks of its last movement. It removes its own movement from the aim. If a teammate is within 95 units of the line, it does not fire21.
  9. Grenade. The cog charges to agree with the distance (4–12.5 m), but not when a teammate is near the target. It does not do a check of its own distance to the blast21.
  10. Sneak. The cog sneaks near the objective when it hears something but sees nothing21.

The measurements of the maintainer show why each habit is there. The new base.bas won 100–0 against the previous baseline. When the maintainer removed one habit, the policy lost: aim 3–37, footwork 12–28, refusal of fights 12–28, squads 16–2418 (not tested again by us). Under rules 37, the dry-route habit gave 89 wins of 120, against 12 of 60 without it. But rules 38 made the routes of the engine avoid slow water, and the advantage of the habit decreased to 59–4118. But in the league of today, plain base.bas play is the lowest group. Its three derivatives get an average Elo outcome of 0.31–0.61, which is less than the top three champions (section 12).

jev.bas and the Heartland starters

jev.bas (2,644 lines) adds an advisor layer to base.bas. One cog in each squad asks the oracle (section 10) to select the heart of the squad from three candidates. Then it tells the squad the selection with a shout ("Alpha, push Forge."), and its squadmates use that selection22. All cogs within 12.8 m can hear a shout. Thus an enemy that is near can learn the plan. With no oracle, jev.bas plays exactly the same match as base.bas in local runs (the same ticks and the same final hash), but it uses approximately 50% more instructions. The header of jev.bas still gives a budget of 20,000 instructions. The Heartland starters ffa.bas and ffa_blind.bas now belong to the separate Heartland coworld, and they do not compile in the teams game (Appendix A).

10 · The other two lanes: advisor oracle and neural BASIC

  • Advisor oracle: a script can ask an LLM, through the host, a yes/no question, a score question, or a selection question. The question does not stop the script, and the answers come some ticks later.
  • The cost goes to the LLM spend limit of the seat for the episode. The paintbot-pw league sets no limit. An experience request can set a limit, and a limit of 0 makes all questions fail.
  • Neural BASIC: a ZIP of manifest.json, policy.bas, and model.bin (up to 16 MiB). In each tick, the script calls native FP32 inference, and the engine uses the output as the command of the cog. Version 0.3.79 wrote this lane again.
  • The number 2 champion, daveey-pw-neural, plays differently from all BASIC policies in the league. It sends no shouts, uses only the gun, takes almost no pickups, and has the best kill/death ratio (1.53).

Advisor oracle

A seat makes a request during one decision: state fields, notes, questions, and criteria. It sends the request with oracleAsk() and keeps the request id in a global. Then, in later ticks, it calls oraclePoll(id) to get the answers23. Each seat can have only one request at a time. There must be a minimum of 24 ticks between two questions. The host clears the draft of a request at the start of each tick23. On hosted leagues, the host sends the request to the LLM sidecar of the platform with a deadline of two seconds. The cost comes from the LLM spend limit of the seat for the episode24. The league does not set episode_player_pod_llm_spend_limit_usd, and the default is no limit. An experience request can set episode_player_llm_spend_limit_usd, which the platform divides across the seats. The stricter limit applies. With a limit of 0, the sidecar refuses each call, so the oracle gives −1. We did not examine two points. First, we do not know if the default model allowlist of the platform accepts the typesafe/jev-1.13 route of the oracle. Second, we do not know if the questions of Beta get answers in league play10. The host writes each question and answer to the private log of the seat. The maintainer measured that the Jev advisor won 20 of 24 full matches against base.bas through the hosted route. Each game had approximately 100 questions18.

Neural BASIC

A neural upload is a ZIP. Its policy.bas usually makes three calls in each tick:

paintbot_observe(neuralObservation())
run_neural_net(neuralModel(), neuralObservation(), neuralLogits(), neuralState())
paintbot_act(neuralLogits())

These calls cost 512, 16, and 128 work units. A script must call each one a maximum of one time in each tick, in this sequence. An incorrect use stops the seat25. paintbot_act replaces the full command for the tick. Thus the engine ignores action calls before it, and action calls after it change it. The inference of the model can use a maximum of 4,000,000 counted operations in each tick at 16 seats. The engine does this check one time, at load. The recurrent state starts again at the start of the match, at each death, and at each respawn25. The teams game has three observation contracts. Version 1 has 448 floats. Version 2 has 506, and it adds terrain. Version 3 has 514, and it adds an 8-float scoreboard: team lives, glory, the award for lives behind, quiet supplies, and the clock. The scoreboard does not include the cogs award of rules 47. Each contract also has a form that accepts up to 128 more values, which BASIC sets with neuralInput26. The action contracts give 82 logits in heads of 51, 25, 2, 2, and 2 (movement, aim, fire, grenade, sneak). Action contract version 2 aims at a point ahead of the target, with the rule of base.bas26. A model has one of two formats. PWNET001 is a fixed MinGRU. PWNET002 is a stack of up to 64 layers from a fixed menu. A schema-2 manifest can add decoder options to the default argmax, for example random samples, holds on fire near teammates, and short strafe legs19. The full contract is in neural_basic.md27 and neural_actor.md28 in the repository. The repository also has a training bridge29.

11 · Engine nuances and traps

  • The game changes many times each day, and league episodes use each new release immediately.
  • A replay is a full record of the actions, with a state hash for each tick. The newest build plays older versions of the rules again exactly.
  • The guide does not agree with the code in some places. In each of those places, the code is correct.
  • outcome: "time_limit" means a draw. It does not mean "the clock stopped the match".
  • Each league episode plays a different seed. The seed: 2026 in its configuration is only a placeholder.
  • On the big generated maps, squared distances overflow int32.

A moving target

The repository released 54 versions in the eleven days from 0.3.25 (2026-09-18) to 0.3.79 (2026-09-29). It released 26 of them on 2026-09-28. Each of rules 34 through 48 changed something30. The changes were losses by elimination, the mirrored fair map, glory, glory hearts, glory for lives behind, and stronger grenades. Then came generated maps, shared team vision, glory that you can configure, and cogs that walk in water to the lake heart. The newest changes are a number of seats for each match (46), glory for cogs behind (47), and fog of war in FFA-kin (48). Releases are automatic, and some changes are only in the configuration. For example, the cogs award went from 5 to 10 in 0.3.77 with no new rules number. Version 0.3.79 changed no rule of the teams game. Its engine changes are the neural lane and telemetry for training only. It also added a controlHeartCount helper, which moved the later lines of mechanics.nim by 89. The lab keeps the engine tag in the release.env pin file31. The pw.py deployed-ref command compares that tag with the build of the league, and it lists the changed files that contain rules. Run it before you trust a rule, and that includes the rules in this report.

Replays re-simulate across versions

A hosted replay is a POLYWORLDREPLAY tape. It has the seed, the command of each seat in each tick, and a state hash for each tick. It also has the names of the players, the full text of each shout, and the match configuration. From rules 46, it also has the number of seats32,7. The header of the tape records the number of the rules, and the simulator keeps the code for all older rules. Thus one current build plays older games again, and the hashes agree exactly. The 0.3.79 build of the lab played all 80 hosted rules-48 league tapes and three rules-44 samples again with no hash error. In a negative control at 0.3.65, we forced rules 45 on the rules-44 tapes, and the hashes did not agree within 26–269 ticks. The hosted images use Nim 2.2.10, and the lab uses Nim 2.2.6 locally. All 83 hosted tapes that we examined played again correctly13. Gods of the Arena is different: its replays play again correctly only at the exact commit of the recording. The replay_stats tool of the repository does not do a check of the hashes. It also counts the hearts held at the end as "captures", and it puts all awards except friendly fire into "quiet-supplies". Thus use the tools of the lab, which use pw_trace13.

Smaller traps

  • time_limit means a draw. matchOutcome gives "time_limit" each time that there is no winner. A match that the meter decides at 10:00 gives "0" or "1"7.
  • Each episode has its own seed. The game_config of an episode shows seed: 2026, but the platform replaces it before the episode starts. The engine seed of a league episode is crc32("<division_id>:<round_index>") mod (2^31 − MAX_PLANNED_EPISODES) + job_index. Thus all 80 episodes in the sample were different worlds from tick 0. In an experience request, an explicit game_config_overrides.seed puts every episode in that one world. For deterministic policies, the request then plays the same match again. Do not set a seed, or use num_episodes: 1 for each seed10,12.
  • The league has no side advantage. Odd seats won 43 of 80 matches (54%, or 51% after an adjustment for the strength of the policies). Local mirror matches of base.bas give 71% odd wins, but that is an effect of the mirror match. Thus balance the sides in local screens, but do not add a side effect to league analysis12.
  • int32 on big maps. base.bas says that "23170² exceeds any squared map distance". That is not true on big-twin-mesas and big-deep-forest, where squared distances wrap (we calculated this from the size of the maps). Those maps have approximately ten times the area of Heartwick, with 100 and 126 hearts. The league plays only on Heartwick.
  • Damage from your own grenade. The blast of a grenade includes the cog that threw it, and base.bas does not do a check of its own distance. The league sample had 100 grenade deaths of throwers, against 164 grenade kills of enemies.
  • Armor makes your gun slower. While armor stays on a cog, the gun cooldown is three times longer. Thus armor gives more life but less damage.

13 · Investigating the game: the lab's tools

  • All tools operate through one dispatcher, pw.py, from the root of the repository. Start with pw.py doctor --json, then use pw.py tools --json.
  • Each tool accepts --json and gives one object (ok, outputs, counts, failures, result, next). The exit codes are 0 for success, 1 when some inputs fail, and 2 for a usage error. Code 3 means that a build or the environment is not available. For code 3, next gives the command that repairs the problem.
  • The tool index comes from the catalog in pw.py, and each tool has its own reference page next to the index.
  • Seven lab skills contain the usual workflows: replay, A/B, diagnosis, scouting, local runs, tuning, and the unattended loop.
  • All replay analysis has a hash check. If a tape does not play again correctly on the pinned build, the tools do not accept it.

The start point is the "Agents: start here" section of the lab guide for agents2. pw.py doctor does a check of the release pin against the build of the league. It also examines the built binaries, the native library, the Python dependencies, the clone of the engine source, and the active player session. For each problem, it shows the exact command that repairs it. pw.py tools shows the catalog: the question that each tool answers, and its inputs and outputs33.

The first steps for a new user. This first hour uses only reads and local runs:

  1. Run pw.py doctor --json (Appendix C gives the full command), and then run each repair command that it shows (usually pw.py build and pw.py build-native).
  2. Read section 1 of the mechanics reference (scoring and rank), and read the policy surface reference before you write BASIC9,19.
  3. Run pw.py scout fetch and pw.py scout report to get recent public league episodes and to make profiles of the champions. Use pw.py episodes <dir> and pw.py metrics to query them.
  4. Write a candidate, and then run pw.py local compile and pw.py local screen against base.bas. Local results find candidates that are clearly worse. They are never evidence about the field.
  5. Upload the candidate, and measure it with a paired hosted A/B (pw.py ab-requests, then pw.py compare). The primary metric is the Elo outcome of each episode. A submission to the league needs the explicit approval of James.

Appendix C: Evidence and analysis commands

Run these commands from the personal_labs_paintbot_pw checkout33,13:

uv run python paintbot_pw_lab/tools/pw.py doctor --json          # readiness, with fix commands
uv run python paintbot_pw_lab/tools/pw.py deployed-ref --json    # league build vs the pinned tag
uv run python paintbot_pw_lab/tools/pw.py build                  # engine binaries at the pinned tag
uv run python paintbot_pw_lab/tools/pw.py episodes <dir> --json  # hash-checked trace + tables for every tape
uv run python paintbot_pw_lab/tools/pw.py metrics <dir>          # per-seat, per-policy, per-team metrics
source paintbot_pw_lab/tools/release.env; B=paintbot_pw_lab/tools/bin/$PW_RELEASE_TAG
$B/paintbot-headless --replay <replay file>                      # engine-only hash check
$B/paintbot-headless --bot paintbot_pw_lab/reference/base.bas:16 --seed 2026 --ticks 2400 \
    '--glory:{"behind_lives":5,"behind_cogs":10}'               # a local match with the league glory config

--bot FILE:N fills the seats in order. Thus a.bas:8 b.bas:8 puts both files on mixed teams. To prevent this, use sixteen --bot FILE:1 flags in alternation, or use pw.py local, which also uses the glory configuration of the league. The local.py script of the repository34 is the exact hosted handoff, and it writes a log for each seat. But it cannot set glory. You can read the hosted log of a seat only for episodes that include one of our policies. All other facts about a match (kills, deaths, pickups, captures, glory by type, the text of shouts) come from the tape through pw.py episodes and pw.py metrics.
